Blooptopia • Grown-Ups' Corner

A Teacher & Family Guide

Blooptopia is a 3D block-coding adventure for Grades K–4. Students pre-program a bouncy ball hero — a Bloop — with direction commands, color conditions, loops, and functions to roll it through floating-island mazes, collecting stars along the way. Every level is solved by writing a program first, then pressing Run and watching it play out.

What Is Blooptopia?

Children don't drive Bloop directly — they write a program that drives it for them. Drag direction commands (and later, color rules, loops, and functions) into a program strip, then press Run to watch Bloop roll the maze exactly as written, or Preview first to see the predicted path traced on the board without spending a run. Bloop rolls in a straight line until it hits an edge or wall, so each command is a real decision about distance, not just direction. Sixty levels across five worlds gradually introduce sequencing, color conditionals, loops, and reusable functions — the same building blocks of real programming languages, in kid-sized form.

How Each Tool Works

Direction Commands

Drag Up / Down / Left / Right blocks into the program strip. Bloop rolls each command in order until it hits an edge or wall, then waits for the next one — the foundation of sequencing.

Color Conditions

Rules like "if pink, turn left" fire every time Bloop rolls onto a matching colored tile. Students reason about a rule that only sometimes applies — a first hands-on conditional (if).

Loops

A loop block repeats a short sub-sequence 2–5 times, so a repeating maze pattern can be solved with a handful of commands instead of writing every step out by hand.

Functions (F1)

Students teach Bloop a named trick once — a function — then call it from the main program wherever that same move set is needed again, avoiding repeated work.

Preview Mode

A free, unscored dry run that draws Bloop's predicted path on the board and reports whether the current program reaches the goal — before a student commits to a real, scored Run.

3-Star & Perfect Scoring

Every level awards up to 3 stars for reaching the goal, plus a PERFECT badge for matching or beating the level's par command count — encouraging students to revise for a shorter program.

Bloop Collection

Coins earned from stars and achievements unlock 16 characters built from 12 accessories and 6 eye styles — a coin-economy reward layer that sits on top of the coding challenges.

Achievements & Badges

63 tiered achievements and 22 world/mastery badges track milestones like first perfect clear or finishing a world, giving students clear, revisitable goals beyond "beat the level."

The Five Worlds

Each world adds exactly one new programming idea on top of everything before it, and each has 12 levels.

World 1 • Bloopberry MeadowsSequences only — direction commands, one after another.
World 2 • Crystal CavernsColor conditions — "if pink, turn left."
World 3 • Loopy CanyonLoops — repeat a short pattern 2–5 times.
World 4 • Function JunctionFunctions — teach Bloop a trick once, call it anywhere.
World 5 • Bugstorm PeaksMastery — sequences, conditions, loops, and functions, combined.

Standards Alignment (CSTA)

Blooptopia spans Grades K–4, so it touches two CSTA bands: Level 1A (K–2) and Level 1B (grades 3–5). Below are only the standards we can honestly justify, each tied to a real mechanic. Use the rows that match what your class actually does.

CSTA Level 1A (Grades K–2)

StandardTitle (CSTA 1A)How Blooptopia addresses it
1A-AP-08 Model daily processes by creating and following algorithms (sets of step-by-step instructions) to complete tasks. Every level is written as an ordered list of direction commands that Bloop must follow exactly — a hands-on algorithm students build before pressing Run.
1A-AP-09 Model the way programs store and manipulate data by using numbers or other symbols to represent information. Direction blocks are symbols (arrows) that stand for real moves; students track stars and coins collected as they plan a route.
1A-AP-10 Develop programs with sequences and simple loops, to express ideas or address a problem. World 1 is pure sequencing; World 3 (Loopy Canyon) introduces simple loops that repeat a pattern to solve a maze.
1A-AP-11 Decompose (break down) the steps needed to solve a problem into a precise sequence of instructions. Longer mazes require breaking the route into stages — roll here, then turn, then roll again — before dragging any blocks in.
1A-AP-14 Debug (identify and fix) errors in an algorithm or program, including problems in a sequence, and describe how they were fixed. When Bloop rolls past the goal or into a wall, students use Preview to see exactly where the program went wrong, then edit and re-check it.

CSTA Level 1B (Grades 3–5)

StandardTitle (CSTA 1B)How Blooptopia addresses it
1B-AP-08 Compare and refine multiple algorithms for the same task and determine which is the most appropriate. The PERFECT/par-command scoring invites students to compare a working solution against a shorter one and decide which is more efficient.
1B-AP-09 Create programs that use variables to store and modify data. A function's remembered move sequence acts like a stored, reusable value that students call by name instead of re-typing it.
1B-AP-10 Create programs that include sequences, events, loops, and conditionals. By World 5, a single program can combine direction sequences, color conditionals, and loops — exactly this standard, built level by level.
1B-AP-11 Decompose (break down) problems into smaller, manageable subproblems to facilitate the program development process. Function Junction levels are explicitly solved by isolating a repeated sub-task, writing it once as F1, and calling it from the main program.
1B-AP-12 Design and iteratively develop programs that combine control structures, including nested loops and compound conditionals. Bugstorm Peaks (World 5) levels nest loops and color conditions together inside the same maze, requiring iterative refinement to solve.
1B-AP-15 Test and debug (identify and fix errors) a program or algorithm to ensure it runs as intended. Preview mode is a built-in test-before-you-commit step; students read the predicted path, diagnose a mismatch, and fix the program before running it for real.

Standard titles are quoted from the CSTA K–12 Computer Science Standards, Levels 1A (K–2) and 1B (grades 3–5).

Ready-to-Run Lesson Plans (25–30 minutes each)

Grade K–1

Lesson 1 — Roll Bloop in the Right Order

25 minutes • whole group then pairs • CSTA 1A-AP-08, 1A-AP-14

Objective: Children build a short sequence of direction commands to guide Bloop from start to goal, and use Preview to find and fix a wrong step.

sequencecommandprogramrunpreview
  1. (4 min) Gather at a shared screen. Open World 1: Bloopberry Meadows, Level 1. Drag one RIGHT block into the program strip together.
  2. (4 min) Press Preview first — watch the dotted path — then press Run and cheer as Bloop rolls.
  3. (5 min) Model a two-turn maze: RIGHT then DOWN. Ask "what order do the commands go in?" before dragging them in.
  4. (9 min) Pairs play through the next few Bloopberry Meadows levels on their own devices, using Preview before every Run.
  5. (3 min) Whole group: one pair demos their favorite level and reads their program aloud, command by command.
Discuss: What happens if the commands are in the wrong order? How did Preview help you before you pressed Run? What did Bloop do when it hit a wall?
Extension: Try to solve a level with one fewer command than you first used.
Grade 2–3

Lesson 2 — If It's Pink, Turn: Color Conditions & Loops

30 minutes • pairs • CSTA 1A-AP-10, 1B-AP-08, 1B-AP-10

Objective: Students use a color-condition rule to make Bloop react differently on different tiles, then use a loop to shorten a repeating pattern, and compare command counts.

conditionifrulelooprepeatpar
  1. (4 min) Introduce Crystal Caverns: "if pink, turn left" is a rule that only fires on pink tiles. Predict what happens on a non-pink tile.
  2. (8 min) Pairs solve two or three Crystal Caverns levels, checking every prediction with Preview first.
  3. (4 min) Move to Loopy Canyon. Show a maze with a repeating step pattern; write it out the long way first.
  4. (8 min) Now solve the same maze with a loop block instead. Compare command counts — which program is shorter?
  5. (4 min) Check for a PERFECT star: did the loop solution beat the level's par command count?
  6. (2 min) Share out: one pair explains their color rule, one explains their loop.
Discuss: When does the color rule not fire? Why is the loop version shorter? Could you use a loop and a color rule in the same program?
Extension: Find a level where a loop makes the program shorter than any sequence-only solution.
Grade 3–4

Lesson 3 — Teach Bloop a Trick: Functions & Mastery Mazes

30 minutes • pairs • CSTA 1B-AP-09, 1B-AP-11, 1B-AP-12, 1B-AP-15

Objective: Students identify a repeated move pattern, capture it as a function (F1), call it from the main program, and debug a combined sequence-loop-condition maze using Preview.

functionreusablecalldecomposedebug
  1. (4 min) Open Function Junction. Find a maze where the same three-move pattern appears twice. Ask: "do we have to write it twice?"
  2. (6 min) Model recording that pattern as F1, then calling F1 twice from the main program instead of repeating the moves.
  3. (8 min) Pairs solve two or three Function Junction levels, each time looking for a repeated pattern to turn into F1.
  4. (8 min) Move to Bugstorm Peaks. Attempt a mastery maze that combines sequences, a color rule, and a loop. Use Preview to find where the plan breaks, then fix one piece at a time.
  5. (4 min) Share out: one pair explains what their function does and why they made it.
Discuss: How did you decide what to put inside the function? What did Preview show you when the program was wrong? Which was hardest to combine — the loop or the color rule?
Extension: Solve a Bugstorm Peaks level for a PERFECT star, then explain out loud why that program can't get any shorter.

Capstone Assessment — "Plan Your Own Maze"

Ask each student (or pair) to sketch a short original maze on paper — including at least one color tile and one repeating stretch — then build it as a program that solves their own maze on the hardest world they've unlocked, and explain their choices out loud. Use the three-level rubric below.

DimensionEmergingDevelopingSecure
Sequencing Needs help ordering commands; frequent wrong-order mistakes. Builds a correct sequence with some trial and error. Plans the full sequence before dragging any blocks in.
Conditions & loops Doesn't yet use color rules or loops without prompting. Uses a color rule or loop with guidance. Chooses a condition or loop independently because it fits the maze.
Functions Repeats the same moves instead of reusing a function. Uses a given function when told to. Spots a repeated pattern and turns it into a function unprompted.
Debugging Gives up or restarts from scratch when a run fails. Uses Preview and fixes an obvious error with help. Reads Preview, diagnoses the exact wrong step, and fixes just that part.
Explaining choices Runs the program with little narration. Names the blocks used (sequence, condition, loop, function). Explains clearly why each block was chosen for that part of the maze.

Keep it playful: the goal is reasoning and persistence, not a perfect score. "Secure" work explains why, not just what.
